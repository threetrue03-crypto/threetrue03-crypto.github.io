# ADC Class

## ADC란
ADC는 `Analog-to-Digital Converter`의 약자이다. 아날로그의 연속적인 값을 컴퓨터가 알아들을 수 있게 디지털 신호로 변환한다는 뜻이다.
아날로그 값인 전압 값은 컴퓨터가 이해하기 매우 어렵다. 그래서 ADC가 특정 순간의 전압을 캐치해서 12비트 숫자로 변환한다. 
MicroPython은 다른 객체와 하드웨어 간의 호환성을 위해 12비트를 16비트로 변환하는 작업을 거친다. 아래 코드를 보면 이해가 된다.

``` C
16bit = 12bit << 4 | 12bit >> 8
```

12비트를 4번 left-shift하여 4비트를 확보한 뒤, 기존 12비트의 상위 비트 4비트를 or연산 하므로써 해당 값을 16비트로 확장할 수 있다.
값을 더 정밀하게 표현한 것이 아니다. 단순히 12비트 값을 16비트로 확장한 것이다. 

예를 들어보자. 1과 2는 12비트로 표현되어 있다.

```
1(10) = 0000 0000 0001(2)
2(10) = 0000 0000 0010(2)
```

해당 값을 16비트로 확장한다고 해보자

```
16(10) = 0000 0000 0001 0000(2)
32(10) = 0000 0000 0010 0000(2)
```

1은 16으로 변하고, 2는 32로 변한다. 하지만 15나 31같은 값은 절대로 표현할 수 없다. 즉 정밀하게 표현되려면 그 사이의 값도 표현될 수 있어야 하지만, 이는 단순히 공간 확장이므로 정밀도가 좋아지지 않는다는 것이다.

| ADC 채널 | 연결 대상    | Pico 보드에서의 상태             |
| -----: | -------- | ------------------------- |
|      0 | GP26     | 외부 핀으로 사용 가능              |
|      1 | GP27     | 외부 핀으로 사용 가능              |
|      2 | GP28     | 외부 핀으로 사용 가능              |

로 정리할 수 있다. 이는 단순히 정리된 정보이므로 그냥 넘어가도 좋다.

## machine.ADC() 생성자의 파라미터
MicroPython에서 ADC 생성자는 다음과 같이 정의된다.

```python
ADC(id, *, sample_ns, atten)
```

### id 파라미터
id에는 GPIO 핀의 값을 넣는다. Pin 객체를 직접 넣을 수도 있다. 이는 MicroPython에서 권장하는 방식이다.
필자도 Pin 객체를 넣는 방식을 주로 사용한다. ADC 생성자 내부에서 Pin객체의 내부 설정을 아래와 같이 변경한다.

```
내부 풀업, 풀다운 비활성화, High-Z 상태로 설정
디지털 GPIO 기능 비활성화
```

```python
adc = ADC(Pin(28))
```

### sample_ns 파라미터
`sample_ns`는 ADC 하드웨어가 해당 전압을 12비트로 전환하는 시간을 조절할 수 있는 파라미터다. 아래와 같이 구조도를 그릴 수 있다.

```
센서 전압
   ↓
입력 채널 선택
   ↓
스위치가 닫힘
   ↓
내부 커패시터가 입력 전압까지 충전
   │
   │ 이 시간이 sample_ns
   ↓
스위치가 열림
   ↓
저장된 전압을 12비트 숫자로 변환
```

`sample_ns`는 ADC가 전압을 읽는 주기의 시간이 아니라, 해당 전압을 12비트로 변환할 때까지 그 전압을 충전하는 시간이라고 생각하면 된다. 그래서 해당 파라미터 값이 너무 짧으면 입력 받았던 전압을 못 채우고 12비트로 변환할 수 있다.

### atten 파라미터
`atten`은 attenuation에서 따온 것이다. attenuation는 감쇠를 의미한다. ADC 하드웨어에 잡히는 전압을 dB(데시벨)과 전압의 관계를 이용하여 감쇠를 어느 정도 할 것인지 계산하여 정해야 한다. 공식은 아래와 같다.

$$
\mathrm{dB} = 20\log_{10}\left(\frac{V_{\mathrm{out}}}{V_{\mathrm{in}}}\right)
$$

ADC에서 지원하는 dB값은 0dB, 2.5dB, 6dB, 11dB이 있다. 해당 변수는 아래와 같다.

```python
ADC.ATTN_0DB
ADC.ATTN_2_5DB
ADC.ATTN_6DB
ADC.ATTN_11DB
```

만약, 입력받는 전압의 절반을 줄이고 싶으면 해당 위 공식을 이용하여 dB를 구해 변수를 설정하면 된다. 전압을 절반으로 감쇠하는 dB은 6dB임을 알 수 있다.

$$
20\log_{10}(0.5) \approx -6.02\,\mathrm{dB}
$$

## RP2040에서 지원하는 machine.ADC() 객체의 메서드

```python
adc = ADC(pin_value)
```

위와 같이 ADC 객체를 `adc`변수에 생성했다고 해보자.

### adc.read_u16()
`adc.read_u16()` 메서드는 ADC 하드웨어에서 읽은 전압 값을 12비트로 변환하게 되는데, 그 값을 16비트로 확장하여 반환하는 메서드이다. 그래서 전달할 파라미터가 없다. 만약 파라미터를 전달하게 되면 `TypeError`가 발생한다. 이는 동기식 함수로 볼 수 있고, 동기식 함수란 저장되어 있는 값을 가져오는 것이 아닌 `ADC 하드웨어 접근` -> `12비트로 변환` -> `16비트로 확장` -> `반환` 을 거친다.

해당 16비트를 다시 전압으로 변환하려면 read_u16()으로 읽은 값을 16비트로 표현할 수 있는 최대값으로 나눠 비율을 구한 뒤 기준 전압으로 곱하면 된다. 

## ESP32 machine.ADC()의 메서드
ESP32는 RP2040에서 지원하는 메서드보다 더 다양한 메서드를 지원한다. RP2040 같은 경우는 `adc.read_u16()`밖에 지원하지 않는다.

### read_uv()
`read_uv()`는 ADC 하드웨어가 읽는 마이크로볼트 단위로 정수형으로 반환한다. 마이크로볼트는 1,000을 나누면 밀리볼트가 되고, 밀리볼트에 1,000을 나누면 볼트가 된다. 즉, 볼트를 얻고 싶으면 해당 메서드의 반환값에 1,000,000을 나눠야 볼트값을 얻을 수 있다.

```python
voltage_v = adc.read_uv() / 1_000_000
```

해당 adc에서 마이크로볼트를 반환하는 것은 선형적이지 않고 특히 낮은 입력 구간에서 비선형성이 존재한다. 그래서 해당 ADC를 초기화할 때 atten인 감쇠값을 설정하여 출력 마이크로전압 값을 보정해야 한다. 매우 작은 값이기 때문에 감쇠 dB를 크게 잡아 적게 감쇠해야 한다.

```python
adc = ADC(Pin(34), atten=ADC.ATTN_11DB)
voltage_uv = adc.read_uv()
```

### init(), deinit()
`init()`은 ADC의 객체를 다시 재설정하거나 `deinit()`으로 해제된 ADC 객체를 다시 초기화한다.

init()의 파라미터는 `atten`밖에 없다. 그래서 해당 감쇠값을 `init()`으로 재설정 할 수 있다. 반환값은 `None`이다.

`deinit()`은 사용하고 있는 adc 객체가 사용하고 있던 하드웨어 자원이나 드라이브 자원을 해제한다. 마찬가지로 반환값은 `None`이다.
이 때, `deinit()`은 그 객체가 가리키고 있는 하나의 채널만 해제하는 것이 아니라, 그 채널이 묶여있는 블록을 해제한다. 그래서 만약 ADC 객체를 재사용하려고 해제하는 경우라면 ADC 객체를 재생성하는 것이 안전하다.

```python
adc = ADC(Pin(30))
(...)
# adc.deinit() 은 위험함. 그냥 아래처럼 재생성.
adc = ADC(Pin(31))
```

그럼 여기서 채널과 블록의 개념이 등장한다. 채널과 블록은 과연 무엇일까?

#### 채널과 블록
우선, ADC 채널은 GPIO 핀 같은 걸 생각하면 된다. 아까처럼 온도 센서같은 핀들이 전부 ADC 채널로 보면 된다.
블록은 ADC 채널들과 ADC하드웨어 그리고 주변 장치들을 전부 묶는 것을 의미한다. 그래서 하나의 블록 안에 여러 개의 채널들이 있고 그 채널들을 MUX로 골라 디지털 값으로 변환시키는 구조를 가진다. 

```
여러 아날로그 입력
      │
      ▼
┌─────────────────────┐
│ 입력 선택기(MUX)     │
│                     │
│ 채널 0 ──┐          │
│ 채널 1 ──┼── 선택 ──┼── ADC 변환기 ── 디지털 값
│ 채널 2 ──┤          │
│ 채널 3 ──┘          │
└─────────────────────┘
         전체가 ADC 블록
```

블록과, 해당 채널이 어떤 블록에 속하는지는 하드웨어를 설계할 때 정해져 있으므로 소프트웨어 개발자가 바꿀 수 없다.

RP2040은 아래 표와 같다.
**RP2040은 블록이 1개임**

| ADC 블록 | 채널 | 연결 대상    |
| ------ | -: | -------- |
| ADC    |  0 | GPIO26   |
| ADC    |  1 | GPIO27   |
| ADC    |  2 | GPIO28   |
| ADC    |  3 | GPIO29   |
| ADC    |  4 | 내부 온도 센서 |

ESP32는 아래 표와 같다.
**ADC1 블록**

|       채널 | 연결 GPIO |
| -------: | ------: |
| ADC1_CH0 |  GPIO36 |
| ADC1_CH1 |  GPIO37 |
| ADC1_CH2 |  GPIO38 |
| ADC1_CH3 |  GPIO39 |
| ADC1_CH4 |  GPIO32 |
| ADC1_CH5 |  GPIO33 |
| ADC1_CH6 |  GPIO34 |
| ADC1_CH7 |  GPIO35 |

**ADC2 블록**

|       채널 | 연결 GPIO |
| -------: | ------: |
| ADC2_CH0 |   GPIO4 |
| ADC2_CH1 |   GPIO0 |
| ADC2_CH2 |   GPIO2 |
| ADC2_CH3 |  GPIO15 |
| ADC2_CH4 |  GPIO13 |
| ADC2_CH5 |  GPIO12 |
| ADC2_CH6 |  GPIO14 |
| ADC2_CH7 |  GPIO27 |
| ADC2_CH8 |  GPIO25 |
| ADC2_CH9 |  GPIO26 |

그래서 ADC 객체를 생성할 때 해당 채널이 어떤 블록에 속하는지 먼저 확인 후 코드를 설계해야 한다. 같은 채널이라도 어떤 블록에 속하는지에 따라 연결 GPIO가 달라지기 때문이기도 하다.

블록에서는 해상도를 지정할 수 있다. RP2040에서는 블록의 해상도가 12bit로 고정되어 있으므로 프로그래머가 바꿀 수 없다. ESP32같은 경우는 block 객체에서 해상도를 변경하거나, adc 객체의 width() 메서드를 사용하여 해상도를 변경할 수 있다.

해상도의 비트 하나의 간격에 따른 전압 범위는 `3.3V / 해상도 비트로 표현할 수 있는 경우의 수` 로 구할 수 있다.

### block()
`block()`은 ADC 채널이 연결된 ADC 블록 객체를 반환한다.

위에서 설명했듯이 block 객체의 init() 메서드의 bits 파라미터에서 해당 해상도를 원하는 비트 수로 변경할 수 있다.

해당 블록의 해상도를 변경하게 되면 그 블록에 속하는 모든 채널의 해상도가 바뀐다고 보면 된다. 위에 블록과 채널의 구조도가 MUX를 통해서 선택되는 구조를 이해하면 왜 블록이 변경되면 해당 채널들이 변경되는지 이해할 수 있다.

```python
block.init(bits=9)
```

ESP32 같은 경우는 해상도 비트 수가 `9`, `10`, `11`, `12`로 정해져 있고 그 외의 값을 넣게 되면 `ValueError`를 발생시킨다.
ESP32-S2같은 경우는 13bit까지 허용한다.

### atten()
`atten()`은 해당 ADC 객체의 감쇠값을 제어할 수 있다. 이는 `init()`으로 감쇠값을 재지정하는 것과 똑같이 작동한다.
아래 두 코드의 의미는 같다고 볼 수 있다.

```python
adc.atten(ADC.ATTN_11DB)
adc.init(atten=ADC.ATTN_11DB)
```

### width()
이것은 위에서 설명했듯이 블록의 해상도를 변경할 수 있다. 조금 다른 점이 있다면 width는 블록 객체가 아니라 그 블록에 속하는 채널의 객체이다. 하지만 채널은 자신이 속하는 블록을 알 수 있기 때문에 해당 채널의 해상도를 변경하더라도 그 블록의 해상도를 건드는 작업을 하기 때문에 사실 블록의 해상도를 바꾸는 것과 똑같다.

```python
adc.width(12)
```

ADC 객체에서는 다음과 같은 상수도 지원한다.

```python
ADC.WIDTH_9BIT
ADC.WIDTH_10BIT
ADC.WIDTH_11BIT
ADC.WIDTH_12BIT
```

ESP32-S2같은 경우는 아래와 같은 13비트 상수까지 지원한다.

```python
ADC.WIDTH_13BIT
```

### read()
`read()`는 adc객체가 속해있는 블록의 해상도에 따라 변환된 정수 값을 읽어온다. 이는 16비트로 변환된 것이 아닌 블록의 해상도에 따라서 변환되어 반환되는 것이니 원시값으로 불리고 `read_u16()`과는 당연히 다르다.

## ADC 클래스를 이용하여 온도 측정 자세하게 설명

### adc.read_u16() 에서 내부 온도를 측정하는 원리 및 코드
MicroPython에서 온도를 측정할 때 ADC 하드웨어가 읽는 전압을 사용한다. 온도에 따라 전압이 달라지는 현상을 이용하여 ADC의 read_u16() 메서드를 사용하여 전압을 온도 값으로 변환한다.

라즈베리파이 공식 문서에는 온도가 증가할 때, 전압이 감소한다고 설명한다. 그래서 필자는 read_u16()으로 어떻게 온도로 변환해낼 수 있는지 알아보았다.

라즈베리파이 공식 문서에서 27도 일 때를 기준으로 잡고 그 전압은 0.706V라고 설명한다. 그리고 온도가 1도 변할 때 전압은 0.001721V 변한다. 현재 온도를 T라고 두었을 때 온도에 따른 전압 변화량은 0.001721(27-T) 이다. 그럼 온도 변화에 따라 센서에 측정되는 전압은 `V_sensor = 0.706 - (0.001721)*(27-T)` 로 적을 수 있다. 현재 온도에 대해서 정리하면 `T = 27-{(V_sensor - 0.706)/0.001721}` 로 계산된다. 아래 작성된 코드는 내부 온도를 구하는 코드이다.

```python
from machine import ADC

temp_adc = ADC(ADC.CORE_TEMP) # 또는 ADC(4)
volt = temp_adc.read_u16() / 65535 * 3.3
temp = 27 - (volt - 0.706) / 0.001721
```
