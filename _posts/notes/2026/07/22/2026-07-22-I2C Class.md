# I2C Class

## I2C Class의 생성자 파라미터

I2C Class의 생성자 파라미터를 정리하자면 아래와 같다.

```python
I2C(
    id,
    *,
    scl=None,
    sda=None,
    freq=400_000,
    timeout=50_000
)
```

### id 파라미터
id 파라미터는 I2C가 사용할 블록 번호를 지정한다. RP2040은 0번 블록이 하나밖에 없으므로 0을 입력한다. ESP32에서는 블록이 2개이므로 원하는 블록을 지정하면 된다.

### scl 파라미터
해당 파라미터는 통신하고 싶은 장치의 SCL 핀이 연결되어 있는 GPIO 값을 Pin객체로 생성하여 넘기면 된다. 어렵지 않다. SCK에 대해서 I2C 통신 파트에서 설명했듯이, I2C에는 SCK가 아니라 SCL이고, 제조사에 따라서 SCK로 적혀져 있는 경우가 있다. 이는 SCL로 해석하고 핀을 연결하면 된다.

### sda 파라미터
해당 파라미터는 통신하고 싶은 장치의 SDA 핀이 연결되어 있는 GPIO 값을 Pin객체로 생성하여 넘기면 된다. 이 또한 어렵지 않다.

### freq 파라미터
freq는 SCL 클럭의 주파수를 설정할 수 있다. 장치가 지원하는 클럭의 최대 속도보다 높은 값을 설정하거나, 또한 너무 낮은 값을 설정하게 되면 통신 실패가 발생할 수 있다.

### timeout 파라미터
timeout은 I2C통신에 오류가 생겼을 때 언제까지 기다려 줄 것인가에 대한 값이다. 만약 통신 시간이 timeout값을 넘어간다면 비정상적인 통신으로 인식하고 해당 통신을 중

### 참고, i2c 통신 시간 측정
필자는 `time` 모듈의 `tick_us()` 메서드를 사용하여 I2C 시간을 측정하였다. 통신 측정을 위한 반복 횟수는 100번으로 잡았고, 해당 데이터는 리스트에 저장하였다. 이때 리스트의 append로 인하여 gc가 실행될 가능성이 있기 때문에 미리 리스트를 반복 횟수만큼 할당해놓고 측정을 시작하였다. 측정 코드는 아래와 같다.

```python
def get_i2c_timeout(func, repeat=100, warm_up=10):
    times = [0] * repeat

    for i in range(warm_up):
        func() # warm-up

    for i in range(repeat):
        start = time.ticks_us()

        func()

        times[i] = ticks_diff(time.ticks_us(), start)

    return [max(times), times]
```

위 코드는 i2c 통신을 하는 func() 함수의 실행을 repeat 만큼 반복하여 times 리스트에 저장한다. timeout 값을 설정할 때는 제일 오래 걸렸던 작업 시간을 기준으로 잡아야 하므로 max(times)를 times와 같이 리스트 형태로 같이 반환하였다. 이 때, func의 warm-up까지 고려하여 정확한 시간 측정을 하였다.  


## I2C Class 메서드

### scan()
I2C와 통신하고 있는 주소를 반환받을 수 있다. 형식은 아래와 같다.

```python
i2c.scan()
```

I2C 통신에서 8비트 중 7비트는 주소값, 1비트는 쓰기 또는 읽기의 여부를 보낸다고 하였다. 해당 반환값도 쓰기/읽기 여부가 포함된 비트열일 것 같지만, 실제로는 7비트 주소만 반환한다. 참고로 반환은 리스트로 한다.

### readfrom()
`readfrom()`은 원하는 장치의 송신값을 읽어올 수 있는 메서드이다. 형식은 아래와 같다.

```python
I2C.readfrom(addr, nbytes, stop=True, /)
```

반환은 bytes 객체로 한다.

#### addr 파라미터
`addr`은 원하는 장치의 주소값 입력하면 된다. 여기서 scan() 메서드를 사용하여 해당 주소 값을 가져와 넣을 수 있다.

#### nbytes 파라미터
`nbytes`는 해당 장치로부터 읽을 바이트 수를 지정한다. 

#### stop 파라미터
`stop`은 i2c 통신 마지막에 해당 `readfrom()`를 마치고 STOP 신호를 보낼 것인지에 대한 여부를 결정할 수 있다.
만약, 다음 코드 줄에서 i2c 통신을 수행해야 한다면 `stop`의 값을 False로 설정하여 STOP 신호를 미룰 수 있다.

####
필자는 다음 i2c 통신이 있을 때 `stop` 파라미터를 False와 True로 설정하는 것이 어떤 차이가 있는지 궁금하였다.
그래서 위와 같이 `time` 모듈의 `ticks_us()` 메서드를 사용하여 비교하였다. 코드는 아래와 같다.
    
```python
from machine import I2C, Pin
import time

i2c = I2C(
    0,
    sda=Pin(20),
    scl=Pin(21),
)
addr = i2c.scan()[0]
warm_up = 10
for i in range(warm_up):
    i2c.writeto(addr, b"\xAB")

repeat = 100
run = 100

# stop=False
stop_false_times = [0] * repeat
for i in range(repeat):
    start = time.ticks_us()
    for j in range(run):
        i2c.writeto(addr, b"\xAB", False)
    stop_false_times[i] = time.ticks_diff(time.ticks_us(), start)

# stop=True
stop_true_times = [0] * repeat
for i in range(repeat):
    start = time.ticks_us()
    for j in range(run):
        i2c.writeto(addr, b"\xAB", True)
    stop_true_times[i] = time.ticks_diff(time.ticks_us(), start)

mean_stop_false_time = sum(stop_false_times) / len(stop_false_times)
mean_stop_true_time = sum(stop_true_times) / len(stop_true_times)

print(f"stop=False일 때 : {mean_stop_false_time}ns")
print(f"stop=True일 때 : {mean_stop_true_time}ns")
```

출력 결과는 아래와 같았다.

```terminal
>>> 
stop=False일 때 : 7863.8ns
stop=True일 때 : 8177.06ns
```

`stop`을 False로 설정했을 때가 True보다 `313.26024ns` 더 빨랐다. 

### readfrom_into()
`readfrom_into()`는 bytes 객체로 반환하지 않고 파라미터로 넘긴 버퍼(<class 'bytearray'>)에 저장하는 구조를 가진다. 위에서 말했던 바이트 객체(<class 'bytes'>)와는 다르다. 참고로 바이트 객체는 수정이 불가능하지만, 바이트 배열은 수정이 가능하다. `readfrom_into()` 형식은 아래와 같다.

```python
i2c.readfrom_into(addr, buf, stop)
```

#### buf 파라미터
`buf` 파라미터는 `bytearray` 객체를 넘긴다. byte 객체와 달리 재사용이 가능하다. buf 파라미터로 읽어오는 값을 덮어쓰기 때문에 `readfrom()` 메서드의 `nbytes` 파라미터 같은 읽어올 바이트 수가 필요하지 않다. bytearray를 생성할 때 배열 크기를 지정하기 때문에 해당 크기만큼 장치로부터 값을 읽어온다.

#### readfrom()과 readfrom_into()의 차이
`readfrom_into()`는 `readfrom()`보다 메모리 할당을 거의 하지 않기 때문에 센서 값을 반복적으로 읽게 된다면 `readfrom_into()`를 사용하는 것이 유리하다.

### writeto()
`writeto()` 는 전달하는 주소에 해당하는 장치에 데이터를 전송하는 메서드이다. 형식은 아래와 같다.

```python
i2c.writeto(addr, buf, stop)
```

해당 파라미터에 대한 설명은 위에서 설명했으므로 패스하겠다.

해당 메서드의 반환값은 ACK 신호의 횟수이다. ACK는 장치에서 1바이트를 잘 받았을 때 보내는 신호이다. 즉 통신을 잘 완료한 바이트 수라고 생각해도 괜찮다. 만약 중간에 NACK 신호가 오게 되면 바이트 전송을 중단하고 stop 파라미터에 따라서 STOP 신호가 출력된다. NACK신호는 통신에 문제가 발생하였을 때 장치에서 보낸다.
