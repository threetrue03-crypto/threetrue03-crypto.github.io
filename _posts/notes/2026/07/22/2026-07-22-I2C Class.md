# I2C Class

## I2C Class의 생성자 파라미터

I2C Class의 생성자 파라미터를 정리하자면 아래와 같다.

```python
I2C(
    id,
    *,
    scl=None,
    sda=None,
    freq=400_000,
    timeout=50_000
)
```

### id 파라미터
id 파라미터는 I2C가 사용할 블록 번호를 지정한다. RP2040은 0번 블록이 하나밖에 없으므로 0을 입력한다. ESP32에서는 블록이 2개이므로 원하는 블록을 지정하면 된다.

### scl 파라미터
해당 파라미터는 통신하고 싶은 장치의 SCL 핀이 연결되어 있는 GPIO 값을 Pin객체로 생성하여 넘기면 된다. 어렵지 않다. SCK에 대해서 I2C 통신 파트에서 설명했듯이, I2C에는 SCK가 아니라 SCL이고, 제조사에 따라서 SCK로 적혀져 있는 경우가 있다. 이는 SCL로 해석하고 핀을 연결하면 된다.

### sda 파라미터
해당 파라미터는 통신하고 싶은 장치의 SDA 핀이 연결되어 있는 GPIO 값을 Pin객체로 생성하여 넘기면 된다. 이 또한 어렵지 않다.

### freq 파라미터
freq는 SCL 클럭의 주파수를 설정할 수 있다. 장치가 지원하는 클럭의 최대 속도보다 높은 값을 설정하거나, 또한 너무 낮은 값을 설정하게 되면 통신 실패가 발생할 수 있다.

### timeout 파라미터
timeout은 I2C통신에 오류가 생겼을 때 언제까지 기다려 줄 것인가에 대한 값이다. 만약 통신 시간이 timeout값을 넘어간다면 비정상적인 통신으로 인식하고 해당 통신을 중

### 참고, i2c 통신 시간 측정
필자는 `time` 모듈의 `tick_us()` 메서드를 사용하여 I2C 시간을 측정하였다. 통신 측정을 위한 반복 횟수는 100번으로 잡았고, 해당 데이터는 리스트에 저장하였다. 이때 리스트의 append로 인하여 gc가 실행될 가능성이 있기 때문에 미리 리스트를 반복 횟수만큼 할당해놓고 측정을 시작하였다. 측정 코드는 아래와 같다.

```python
def get_i2c_timeout(func, repeat=100, warm_up=10):
    times = [0] * repeat

    for i in range(warm_up):
        func() # warm-up

    for i in range(repeat):
        start = time.ticks_us()

        func()

        times[i] = ticks_diff(time.ticks_us(), start)

    return [max(times), times]
```

위 코드는 i2c 통신을 하는 func() 함수의 실행을 repeat 만큼 반복하여 times 리스트에 저장한다. timeout 값을 설정할 때는 제일 오래 걸렸던 작업 시간을 기준으로 잡아야 하므로 max(times)를 times와 같이 리스트 형태로 같이 반환하였다. 이 때, func의 warm-up까지 고려하여 정확한 시간 측정을 하였다.  


## I2C Class 메서드

### scan()
I2C와 통신하고 있는 주소를 반환받을 수 있다. 형식은 아래와 같다.

```python
i2c.scan()
```

I2C 통신에서 8비트 중 7비트는 주소값, 1비트는 쓰기 또는 읽기의 여부를 보낸다고 하였다. 해당 반환값도 쓰기/읽기 여부가 포함된 비트열일 것 같지만, 실제로는 7비트 주소만 반환한다.
