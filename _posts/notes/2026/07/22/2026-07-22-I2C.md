# I2C

## I2C란?
`I2C`는 Inter-Integrated Circuit의 약자이다. Inter는 "~사이에", Integrated는 "통합된", Circuit은 "회로" 이므로, 두 개 사이에 통합된 회로라고 해석할 수 있다.
더 정확하게 이야기해보면 두 개의 신호선만 사용해서 데이터를 주고 받는 직렬 통신 방식이라고 할 수 있다. 직렬 통신이란 데이터를 순차적으로 하나씩 하나씩 보내는 통신 방식을 말한다.

## I2C 회로 구조
I2C의 회로 구조는 아래와 같이 SDA은 풀업 저항 구조로 구성되어 있고, SCL도 마찬가지로 풀업 저항으로 구성되어 있다.

```
                 3.3V
                  │
              풀업 저항
                  │
Pico ─────────── SDA ─────────── OLED
 │                │                │
 └─ 트랜지스터 ─ GND     트랜지스터 ─ GND
```

풀 저항에 대해서는 Pin Class에서 주로 다루었으니 설명하지 않겠다.

### SDA
`I2C`에서는 `SDA`와 `SCL`의 통신선을 사용한다. SDA는 Serial Data의 약자이며 실제 데이터를 0과 1로 전달한다. 
OLED 화면으로 예를 들면 A를 출력하기 위해 해당 문자에 맞는 픽셀 데이터를 보낸다.

```SDA
1 0 1 0 0 1 1 0 ...
```

하지만, 데이터만 보내면 도대체 어디가 시작이고 어디가 끝인지 즉 다시말해서 도대체 비트를 언제부터 읽어야 하는지에 대한 정보가 없으면 해당 비트열이 A인지 T인지 종료인지 전혀 알 수가 없다. 그래서 SCL을 도입한다.

### SCL
SCL은 Serial Clock Line의 약자이다. 종종 제조사에서 하드웨어를 설계할 때 SCK라고 적는 경우가 있다. 이는 SPI통신 방식에서 사용하는 Serial Clock의 약자로써 I2C 통신과는 전혀 다른 개념이다. I2C에서는 SCL이 맞다.

SCL은 SDA 비트를 언제 읽어야 하는지 알려준다. Pico CPU의 클럭 주기로 HIGH, LOW로 바뀐다. 이 때는 고-임피던스 상태이므로 풀업 저항으로 인해 놓으면 HIGH, 연결하면 LOW이다. SCL 펄스 하나가 SDA 데이터 하나에 대응되면서 통신한다.

## I2C의 통신 방식
I2C의 통신 방식은 결국 SDA를 어떻게 주고 받는지에 대한 규칙을 이해하면 된다. SDA는 SCL이 HIGH일 때 데이터를 읽고, SCL이 LOW일 때 데이터를 바꿈으로써 원하는 비트열을 송수신한다. 이 때 비트열은 무조건 1바이트 단위로 보내고 받는다. 비트값 `1`, `0` 을 보내는 과정은 아래와 같다.

```
# 1을 보내는 과정
1. SCL을 LOW로 만든다.
2. SDA를 놓는다..
3. 풀업 저항으로 인해 HIGH가 된다.
4. SCL을 HIGH로 만든다.
5. 수신 장치가 HIGH을 읽는다.
6. SCL을 LOW로 만든다.
```

```
# 0을 보내는 과정
1. SCL을 LOW로 만든다.
2. SDA를 GND로 향하는 스위치를 닫는다.
3. SDA는 LOW값을 가진다.
4. SCL을 HIGH로 만든다.
5. 장치가 HIGH를 읽는다.
6. SCL을 LOW로 만든다.
```

결국 SCL이 HIGH 일 때는 SDA를 유지한 상태로 읽고, LOW일 때는 SDA를 바꾸는 작업인 것으로 이해하면 된다.
하지만, SCL이 HIGH일 때 SDA를 유지하지 않고 바꾸는 경우가 있다. 바로 `START`와 `STOP`이다. 

`START`일 때는 SCL이 HIGH일 때 SDA를 HIGH에서 LOW로 바꾼다.
`STOP`일 때는 SCL이 HIGH일 때 SDA를 LOW에서 HIGH로 바꾼다.

ACK와 NACK에 대해서도 설명하겠다. ACK는 Acknowledgment의 약자이다. 즉, OK 사인과 동일하다. 1바이트 비트열을 전부 보내고 나면 그 다음 비트는 무조건 ACK와 NACK을 구별하는 비트로 정해져 있다. 

만약 9번째 비트에서 SDA가 LOW면 ACK이고, HIGH면 NACK이다. NACK은 데이터를 받았는데 장치가 준비되어 있지 않았거나, 해당 데이터가 만약 주소였다면 자신의 장치 주소와 일치하지 않을 때를 보통 의미한다.

이제 OLED에서 'A'를 출력하는 과정을 설명해보겠다.

우선 Pico에서 SCL이 HIGH 일 때, SDA를 HIGH에서 LOW로 바꿈으로써 START를 장치들에게 알린다. 장치는 oled, b, c, d가 있다고 해보자.
각 장치들은 SCL이 LOW에서 HIGH로 바뀌기 전까지, 즉 클럭이 한 번 뛰기 전까지 통신할 준비를 한다.

이후 다음 클럭 때 SDA에서 oled 주소를 흘려 보낸다. oled, b, c, d는 SDA 선을 통해 pico가 보내는 비트열을 받는다. 8번째 비트까지 왔을 때 해당 주소를 자신의 주소와 비교한다. 만약 자신의 주소와 일치하면 ACK을 보내고(SCL이 HIGH일 때, SDA선으로 LOW를 보냄), 일치하지 않으면 NACK을 보낸다.(SCL이 HIGH일 때, SDA선으로 HIGH를 보냄)
