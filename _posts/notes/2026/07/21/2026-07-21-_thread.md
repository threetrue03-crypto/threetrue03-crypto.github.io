# _Thread

## thread란?
일반적으로 프로그램은 직렬처럼 동작한다. 여기에 쓰레드를 적용하게 되면 병렬적으로 작업을 처리할 수 있게 된다.

전체적인 쓰레드 실행 흐름은 다음과 같다.

```
Python
├─ 스레드 1: 작업 A → 작업 B → 작업 C
└─ 스레드 2: 작업 X → 작업 Y → 작업 Z
```

저 쓰레드들은 실제로 CPU 안에 있는 코어들이 작업을 수행한다. CPU 내부는 다음과 같다.

```
CPU
├─ 물리 코어 0
├─ 물리 코어 1
├─ 물리 코어 2
└─ 물리 코어 3
```

물리 코어 안에는 논리 코어가 존재한다. OS는 물리 코어에 직접 배정하지 않고 논리 코어에 작업을 배정시킨다.
만약, 아래와 같이 물리 코어 안에 논리 코어가 2개라면 운영 체제는 마치 코어가 8개인 것처럼 프로그램을 가동시킬 수 있다.

```
CPU
├─ 물리 코어 0
│  ├─ 논리 코어 0
│  └─ 논리 코어 1
├─ 물리 코어 1
│  ├─ 논리 코어 2
│  └─ 논리 코어 3
├─ 물리 코어 2
│  ├─ 논리 코어 4
│  └─ 논리 코어 5
└─ 물리 코어 3
   ├─ 논리 코어 6
   └─ 논리 코어 7
```

그럼 왜 물리 코어안에 여러 개의 논리 코어로 나누는 것일까?
실제로 하나의 작업만 실행하면 모든 장치들이 100% 실행되는 것이 아니다.

예를 들어 작업 A가 메모리 데이터를 기다리는 동안 다른 연산 장치들은 대기할 수 있다. 이 때 같은 물리 코어 내부에 다른 논리 코어에 해당 연산 장치를 사용하는 작업을 배정하면 효율적으로 처리할 수 있게 된다. 그래서 물리 코어 안에 논리 코어를 여러 개 두는 것이다.

자신의 물리 코어와 논리 코어를 확인하려면 `psutil`를 사용할 수 있다. 참고로 `os`의 `cpu_count()`는 논리 코어만 반환한다.

```python
import psutil

print("물리 코어 수:", psutil.cpu_count(logical=False))
print("논리 코어 수:", psutil.cpu_count(logical=True))
```

### 경쟁 상태
두 쓰레드가 동시에 똑같은 변수 접근을 한다고 해보자. 코어들은 스레드의 스택이나 실행된 위치 빼고는 같은 전역 변수와 객체를 바라본다. 그래서 코어들의 경쟁 상태가 발생하는 것이다. 경쟁 상태란 두 개 이상의 코어가 공유된 데이터를 사용했을 때 결과가 실행 순서에 따라 달라지는 현상이다. 아래와 같은 모식도를 봐보자.

```
초기 count = 10

Core 0                         Core 1
──────────────────────        ──────────────────────
count에서 10을 읽음           count에서 10을 읽음
10 + 1 계산                   10 + 1 계산
11 저장                       11 저장
```

Core 0에서 1을 증가시키고, Core 1에서도 1을 증가시켰으므로 마지막 count의 결과 값은 `12`가 되어야 할 것 같지만,  실제로 코어들이 연산 하기 전 동시에 읽는 값은 10이므로, count에 덮어씌울 때 11로 덮어씌워지는 것이다. 그래서 이를 해결하려 Lock을 보통 사용한다.

### Lock
Lock은 공유 데이터를 한 번만 접근 가능하도록 제한하는 것을 의미한다. 아까와 같은 상황을 예로 들어보면, core 0이 count에 접근하고 있을 때는 core 1이 count에 접근할 수 없다. 동작 원리는 해당 쓰레드가 lock을 가지고 있을 때만 공유 자원을 사용하도록 코드를 설계하면 문제 없이 원하는 결과값을 얻을 수 있다. 원리와 사용 방법은 아래 코드와 같다.

```
Core 0이 Lock 획득
        │
        ▼
공유 자원 사용 중
        │
Core 1은 대기
        │
        ▼
Core 0이 Lock 해제
        │
        ▼
Core 1이 Lock 획득
```

```python
import _thread

count = 0
lock = _thread.allocate_lock()


def add_count():
    global count

    for _ in range(1000):
        with lock:
            count += 1
```

### Thread 중지 방법
MicroPython에서는 thread를 강제로 종료하는 `kill()`이나 `stop()` 메서드가 없기 떄문에 이럴 땐 오히려 공유 데이터를 이용한다.
flag를 하나 만들고 스레드를 생성하여 작업을 수행시킨 다음 main 같은 코어 단계에서 해당 플레그 값을 조절하면 Thread가 종료되도록 유도할 수 있다. 참고로 스레드가 자원을 해제하고 나올 때는 해당 스레드의 코드가 종료되었을 때이다. 아래 코드를 남겨두겠다.

```python
import _thread
import time

running = True


def worker():
    while running:
        print("작업 중")
        time.sleep(0.5)

    print("worker 종료")


_thread.start_new_thread(worker, ())

time.sleep(5)
running = False
```

## thread 파라미터와 메서드
전체 구조부터 먼저 보이고 설명을 진행하겠다.

```
_thread 모듈
├─ start_new_thread()
├─ allocate_lock()
├─ get_ident()
├─ stack_size()
├─ exit()
└─ LockType
   ├─ acquire()
   ├─ release()
   ├─ locked()
   ├─ __enter__()
   └─ __exit__()
```

### _thread.start_new_thread()
`_thread.start_new_thread()`는 새로운 스레드를 생성하고 그 스레드에 함수를 넘긴다.

```python
_thread.start_new_thread(function, args, kwargs)
```

#### function
스레드에 전달할 funcion을 지정한다. 이후 등장할 args와 kwargs를 위해서 해당되는 function의 파라미터를 잘 알아두어야 한다.

#### args와 kwargs
`args`와 `kwargs`는 function에 지정되어 있는 파라미터를 넘기는 것이다. args는 위치 기반으로 파라미터를 넘기고 kwargs는 키워드 기반으로 파라미터를 넘긴다.

```python
def func1(a, b, c):
   pass
```

이렇게 작성 되어 있다고 했을 때, `args`를 통해서 넘기려면 아래와 같이 작성하면 된다.

```python
_thread.start_new_thread(func1, (10, 20, 30))
```
